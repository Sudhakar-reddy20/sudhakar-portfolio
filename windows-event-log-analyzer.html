01 / WHAT I BUILT

Windows Security Event triage

The analyzer reads exported Windows Event XML rather than raw EVTX binary files. It extracts event metadata and selected event data, then evaluates the records for authentication and security-relevant account/audit changes.

Authentication activity

Event 4625 represents failed logons and 4624 represents successful logons. The analyzer groups events by source IP where that field is available.

Account and audit changes

Events 4720, 4728, 4732 and 1102 are surfaced for analyst review because they can indicate account creation, group membership changes, or audit-log clearing.

03 / DETECTION RULES

Three rules implemented

WELA-001HIGH · PROJECT LABEL

Repeated failed logons

Counts Event ID 4625 records from the same source IP within a configurable rolling time window. It emits one alert per continuous burst, avoiding repeated alerts for overlapping windows.

WELA-002CRITICAL · PROJECT LABEL

Successful logon after failures

Checks each Event ID 4624 for the configured number of preceding Event ID 4625 events from the same source IP within the configured time window.

WELA-003REVIEW

Security-relevant account and audit changes

Flags Event IDs 4720, 4728, 4732 and 1102 for analyst review. These events are surfaced as investigation leads, not automatically classified as malicious.

Clone the repository and run the analyzer against its included synthetic XML dataset:

cd threatlens/projects/windows-event-log-analyzer

06 / LIMITATIONS

Scope and responsible use

  • Analyzes exported XML; it does not read live Windows event channels or parse raw EVTX binaries.
  • Detection is rule-based and can produce false positives or miss activity outside configured rules.
  • Source IP can be absent or unavailable depending on event type and audit policy.
  • No account disabling, IP blocking, or other automated response is performed.
  • Use only logs you own or are authorized to analyze; preserve originals and protect sensitive records.
